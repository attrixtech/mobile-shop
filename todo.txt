# MASTER SOFTWARE DEVELOPMENT PROMPT
# Mobile Shop Management ERP – Webotapp
The design should be compact
## 1. Project Overview

Build a complete, production-ready, multi-tenant Mobile Shop Management ERP for Indian mobile phone retailers, smartphone dealers, electronics stores, mobile repair shops, and multi-branch retail businesses.

The application must manage the complete lifecycle of a mobile retail business, starting from purchasing smartphones from distributors to inventory management, IMEI tracking, sales, GST invoicing, customer management, repair services, warranty tracking, exchanges, accessories sales, payments, accounting, and business analytics.

The system must be suitable for:
- Small independent mobile shops.
- Multi-brand mobile retail stores.
- Authorized mobile phone dealerships.
- Smartphone and accessories retailers.
- Mobile repair and service centers.
- Wholesale and retail mobile distributors.
- Multi-branch electronics businesses.

The software must be designed as a commercial SaaS product under the brand **Webotapp Mobile Shop ERP**.

Do not build a simple billing application. Build a comprehensive retail management platform with real operational workflows.

## 3. Multi-Tenant SaaS Architecture

The system must support multiple independent mobile shop businesses using one application.

Each business must have:
- Company profile.
- GSTIN.
- Business address.
- Contact details.
- Logo.
- Invoice configuration.
- Branches.
- Employees.
- Suppliers.
- Customers.
- Products.
- Inventory.
- Financial records.
- Subscription plan.

Implement tenant-level data isolation.

One business must never access another business's:
- Customers.
- Products.
- Stock.
- IMEI records.
- Invoices.
- Purchases.
- Employees.
- Financial information.

Use a shared database with tenant_id or an equivalent properly implemented tenancy architecture.

Every tenant-owned record must be scoped securely.

Create a platform super-admin who can manage tenants, subscriptions, plans, usage, and platform configuration.

# 34. DEVELOPMENT INSTRUCTIONS FOR THE AI CODING AGENT

Follow these instructions strictly:

1. First inspect the existing project directory, framework, dependencies, routes, database schema and current functionality.
2. If a Laravel project already exists, extend it rather than creating a duplicate application.
3. Do not overwrite existing working code without understanding its purpose.
4. Prepare the database architecture before building business modules.
5. Create migrations, models, controllers, services, policies, requests, views and tests in a structured manner.
6. Keep business logic out of controllers wherever practical.
7. Use database transactions for all important financial and inventory operations.
8. Use reusable components and services.
9. Implement real functionality. Do not create decorative buttons or fake dashboard numbers.
10. Do not leave important workflows as TODOs or placeholders.
11. Use realistic sample data for development and demonstrations.
12. Add validation and meaningful error messages.
13. Ensure every module works with tenant and branch permissions.
14. Test each phase before proceeding to the next.
15. Maintain a DEVELOPMENT_PROGRESS.md file showing completed modules, pending modules, known issues and next steps.
16. Maintain a README.md with installation, configuration, migrations, queues, scheduler and deployment instructions.
17. Provide database seeders for demo tenants, products, smartphones, IMEIs, customers, suppliers and transactions.
18. Never expose real customer or financial information in demo environments.
